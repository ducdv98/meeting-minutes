# Dependency licenses for an Apache-2.0 app release

Date: 2026-10-15

## Verdict

**The app's own code can be offered under Apache-2.0, but the current Windows installer needs license work before release.** Its MP3 encoder uses `mp3lame-encoder` and `mp3lame-sys` (LGPL-3.0), and the latter statically links vendored LAME. Apache-2.0 on the app does not relicense those components. The installer must satisfy the LGPL requirements for the combined work, or the owner must replace that encoder. MPL-2.0 Rust dependencies and OFL-1.1 fonts can coexist with Apache-2.0 when their own terms and notices are preserved. No registry Rust dependency has an unknown license field, and none is GPL-only or AGPL. The brand pack has **no recorded reuse grant**; the owner must establish its rights and state explicitly whether artwork is excluded from the code license. [LGPL-3.0 §4](https://www.gnu.org/licenses/lgpl-3.0.html), [MPL-2.0 distribution FAQ](https://www.mozilla.org/en-US/MPL/2.0/FAQ/), [OFL FAQ](https://openfontlicense.org/ofl-faq/), [ADR 0013](../adr/0013-open-source-app-private-managed-service.md).

## Audit method and scope

- Compared **all 595 packages** in [`Cargo.lock`](../../Cargo.lock) with `cargo metadata --format-version 1 --locked --offline`: 591 registry packages have a license expression; the four packages without one are this repository's workspace packages (`meeting-minutes`, `meeting_minutes_core`, `meeting_minutes_whisper`, and `capture-spike`). The missing workspace declarations are the owner's pending license-field decision, not an unidentified third-party crate. Windows inclusion of the flagged packages was checked with `cargo tree -p meeting-minutes --target x86_64-pc-windows-msvc --edges normal,build --offline`.
- Read the installed `package.json` and license files for **all ten direct production dependencies** in [`package.json`](../../package.json). Development-only npm packages are outside this requested production audit. The exact built third-party file set should be checked again against the release artifact after dependency updates.
- Inspected the vendored source in cached `whisper-rs-sys 0.15.0` and `mp3lame-sys 0.1.11`, the model download code, font package license files, the [Tauri bundle config](../../src-tauri/tauri.conf.json), and brand provenance notes. These are metadata and source checks; no Windows installer was built here.

## NOTICE and third-party texts

**An Apache-2.0 `NOTICE` file is not automatically required.** Apache-2.0 §4(d) requires carrying an upstream Apache work's NOTICE attributions when that work supplies a NOTICE. The 408 locked Rust packages whose license expression includes Apache-2.0 and the direct npm Apache packages were checked for top-level `NOTICE*` files; none was found. This is a package-content observation, not a guarantee about a future dependency set. [Apache-2.0 §4](https://www.apache.org/licenses/LICENSE-2.0.html).

**A release-accessible third-party notices document is still needed.** It can be named `NOTICE` or `THIRD_PARTY_NOTICES`; the title does not replace the underlying licenses. It should carry the exact vendored whisper.cpp/ggml MIT notice; the Inter and Be Vietnam Pro package copyright lines and OFL text; the LGPL-3.0 wrapper texts (including the incorporated GPL-3.0 text), vendored LAME v2-or-later license text and source/relink information; MPL-2.0 notice and source location for the covered crates; and the copyright/license texts required by bundled MIT/BSD/ISC/Unicode and other dependencies. If any Apache dependency with a NOTICE is later added, reproduce its required attribution there or in another location allowed by §4(d). Make this document available to installer recipients, not solely in the source repository. [MIT license condition](https://github.com/ggml-org/whisper.cpp/blob/master/LICENSE), [OFL FAQ](https://openfontlicense.org/ofl-faq/), [LGPL-3.0 §4](https://www.gnu.org/licenses/lgpl-3.0.html), [MPL-2.0 §3](https://www.mozilla.org/en-US/MPL/2.0/).

## Exact steps remaining for the owner

1. Choose whether to keep the statically linked LAME encoder. If keeping it, prepare and verify the LGPL-compliant Windows distribution package (license texts, source, relinkable application material and instructions, and any installation information the license requires). If replacing it, rerun this audit after the code and lockfile change.
2. Establish the brand pack's ownership and redistribution terms, then explicitly label the original and derived images as included in or excluded from the app-code license. Replace artwork whose rights cannot be confirmed.
3. Prepare the release-accessible third-party notices and covered-source/relink locations described above. Verify their presence in an actual Windows installer or its accompanying distribution, including the two OFL font notices and vendored MIT notice.
4. After those decisions, add the owner's Apache-2.0 `LICENSE` and manifest license fields, update the README/site wording, and repeat the inventory against the final lockfile and installer. Those implementation steps belong to the remainder of ticket 09 and were intentionally not done here.
