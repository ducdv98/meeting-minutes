# Windows transcription and meeting-scoped Ask research

Research date: 2026-10-12. Prices are public USD list rates checked on this date, before discounts, taxes, storage, or network charges. **RTF** below means processing time ÷ audio duration; lower is faster. This is a feasibility assessment, not a benchmark of the app on a Windows laptop.

## Verdict and recommended path

**Feasible.** A 60-minute meeting can be transcribed after the user presses **Transcribe**, saved as ordered, application-owned segments with stable IDs and integer millisecond audio ranges, and queried within that meeting. The first Windows implementation should use **local multilingual Whisper through `whisper.cpp`** (CPU baseline, optional Vulkan/CUDA acceleration) and **local retrieval plus a user-selected Ask provider**. Default Ask to a local model only when the machine can run one with an adequate context budget; otherwise offer explicit cloud Ask via BYOK. Keep audio and transcripts on the device unless the user explicitly chooses a cloud operation. `whisper.cpp` documents Windows, CPU and several GPU backends; OpenAI's Whisper model card confirms multilingual support but warns of uneven language accuracy and hallucinations. [whisper.cpp](https://github.com/ggml-org/whisper.cpp), [Whisper model card](https://github.com/openai/whisper/blob/main/model-card.md)

Start with **multilingual `small`** as the practical CPU quality/speed trial, let users choose `base` for weak hardware and `medium`/`large-v3-turbo` after a device benchmark, and retain the original audio for correction. Do not use the `.en` checkpoints for Vietnamese. This is an engineering recommendation, not a published English/Vietnamese meeting WER result. OpenAI lists model sizes and says accuracy varies across languages; its tokenizer includes Vietnamese. [Whisper README](https://github.com/openai/whisper), [Whisper language list](https://github.com/openai/whisper/blob/main/whisper/tokenizer.py), [Whisper model card](https://github.com/openai/whisper/blob/main/model-card.md)

For a **managed cloud** option, Deepgram Nova-3 or AssemblyAI Universal-3.5 Pro expose word timing and diarization together; OpenAI `whisper-1` is a simple timestamped fallback. A stronger OpenAI `gpt-4o-transcribe` text result should **not** be substituted for timestamped segments: OpenAI says to use `whisper-1` for word/segment timestamps. [Deepgram diarization](https://developers.deepgram.com/docs/diarization), [AssemblyAI speaker labels](https://www.assemblyai.com/docs/pre-recorded-audio/label-speakers), [OpenAI file transcription](https://developers.openai.com/api/docs/guides/speech-to-text)

[NVIDIA model card](https://huggingface.co/nvidia/parakeet-tdt-0.6b-v3) | Optional English fast path after Windows packaging and local speed/accuracy tests; cannot be the bilingual default. |

OpenAI's Whisper checkpoints range from 39M (`tiny`) to 1.55B (`large`) parameters; `small` is 244M and `turbo` about 0.8B. The Whisper README gives approximate VRAM needs of ~1GB (`tiny`/`base`), ~2GB (`small`), ~5GB (`medium`), ~6GB (`turbo`) and ~10GB (`large`); `whisper.cpp` lists approximate disk/RAM footprints of 75MiB/~273MB (`tiny`), 142MiB/~388MB (`base`), 466MiB/~852MB (`small`), 1.5GiB/~2.1GB (`medium`) and 2.9GiB/~3.9GB (`large`). These are different runtime formats and cannot be compared as identical memory requirements. [Whisper README](https://github.com/openai/whisper), [whisper.cpp README](https://github.com/ggml-org/whisper.cpp)

**Speed evidence and limits.** The `faster-whisper` maintainers report the following on **13 minutes** of test audio, not a 60-minute Windows laptop. The rightmost column is a linear extrapolation (`reported time × 60/13`), useful for planning only; long recordings, silence, beam settings, thermal throttling, language and diarization can change results. [Maintainer benchmark and hardware](https://github.com/SYSTRAN/faster-whisper)

| Hardware / model / implementation | Reported 13-min time | RTF | Implied 60-min time |
| --- | ---: | ---: | ---: |
| i7-12700K, 8 threads, `small`, `whisper.cpp` CPU | 2m05s | 0.160 | ~9.6 min |
| Same CPU/model, `whisper.cpp` OpenVINO | 1m45s | 0.135 | ~8.1 min |
| Same CPU/model, `faster-whisper` int8 | 1m42s | 0.131 | ~7.8 min |
| Same CPU/model, batched int8 | 51s | 0.065 | ~3.9 min; more RAM |
| RTX 3070 Ti 8GB, CUDA 12.4, `large-v2`, `faster-whisper` fp16 | 1m03s | 0.081 | ~4.8 min |
| Same GPU/model, batched fp16 | 17s | 0.022 | ~1.3 min; ~6.1GB VRAM |

The defensible CPU-only statement is **faster than real time on the cited desktop with `small`**, with no guarantee for a thin laptop. The GPU result is a discrete NVIDIA example; no cited source establishes a representative Copilot+ NPU RTF for a full multilingual, timed 60-minute transcript. Benchmark supported CPU/iGPU/dGPU/NPU classes on actual target laptops before promising completion times. [Maintainer benchmark](https://github.com/SYSTRAN/faster-whisper), [Windows AI speech requirements](https://learn.microsoft.com/en-us/windows/ai/apis/speech-recognition)

**Accuracy and timing.** Whisper supports English and Vietnamese; English-only checkpoints typically do better for small English models, but cannot transcribe Vietnamese. Its model card warns that accuracy varies with language/accent and that it can hallucinate speech or repeat text. Word timestamps from Whisper are alignments/inferences, not millisecond-accurate ground truth; store integer milliseconds as the app's range unit without promising millisecond acoustic precision. Evaluate English, Vietnamese and code-switched meeting audio using WER/CER plus boundary and citation-click accuracy before model selection. [Whisper README](https://github.com/openai/whisper), [language list](https://github.com/openai/whisper/blob/main/whisper/tokenizer.py), [model card](https://github.com/openai/whisper/blob/main/model-card.md), [Whisper word timing implementation](https://github.com/openai/whisper/blob/main/whisper/transcribe.py)

## 3. Speaker attribution

**Cheap two-channel attribution:** record microphone and WASAPI loopback as separate synchronized tracks. A mic-only speech span can be labeled **“me”** and a loopback-only span **“remote audio”** with confidence checks. Windows loopback captures the rendered endpoint mix (or, with process loopback, a selected process tree); it does not identify each remote person. Speaker audio can bleed into the microphone, and local speech can echo into the loopback, so overlapping spans should remain unknown or mixed until checked. This is a signal-routing inference from Microsoft's capture semantics, not speaker recognition. [WASAPI loopback](https://learn.microsoft.com/en-us/windows/win32/coreaudio/loopback-recording), [process loopback sample](https://learn.microsoft.com/en-us/samples/microsoft/windows-classic-samples/applicationloopbackaudio-sample/)

For actual **remote speaker A/B** separation, `pyannote.audio` Community-1 runs locally after accepting its Hugging Face model terms and can use CUDA; its published speed example uses an H100 and cannot be projected to a normal laptop. `sherpa-onnx` also ships offline diarization components with Windows x64/ARM64 support. Both add model packaging and overlap/identity-error work; treat speaker names as optional editable labels, not as required evidence IDs. [pyannote.audio](https://github.com/pyannote/pyannote-audio), [sherpa-onnx](https://github.com/k2-fsa/sherpa-onnx), [sherpa models](https://k2-fsa.github.io/sherpa/onnx/index.html)

## 4. Meeting-scoped Ask

The target hour is approximately **10,000 transcript tokens** by the project assumption; actual count depends on speaking rate, language and tokenizer. Add IDs, system instructions, the question and output budget before comparing against a model's context window. A full-transcript prompt can be useful for global questions if it truly fits; a local lexical/semantic retrieval index with neighboring segment expansion should be the ordinary path. The retrieval index must be keyed by `meeting_id` and transcript revision, and only that meeting's evidence may enter Ask. This is a design recommendation rather than a provider feature. [Ollama context documentation](https://docs.ollama.com/context-length), [OpenAI token-counting guide](https://developers.openai.com/api/docs/guides/token-counting)

| Ask route | Feasibility and tradeoff |
| --- | --- |
| **Ollama** | Native Windows install, localhost API and NVIDIA/AMD acceleration; schema output is available. Its current default context is **4k below 24GiB VRAM**, too short for the assumed complete transcript, but configurable upward at memory cost. Choose a multilingual instruct model with a verified >=16k context, or retrieve a few thousand tokens per question. Quality/latency on a CPU-only laptop is a product test, not established by its API docs. [Windows](https://docs.ollama.com/windows), [context](https://docs.ollama.com/context-length), [structured output](https://docs.ollama.com/capabilities/structured-outputs) |
| **`llama.cpp`** | Native local inference/server and GGUF quantization; its server supports constrained JSON/schema response formatting. Gives more control over packaging and quantization, with more integration work. Evaluate citation faithfulness separately from model speed. [Project](https://github.com/ggml-org/llama.cpp), [server](https://github.com/ggml-org/llama.cpp/blob/master/tools/server/README.md) |
| **Foundry Local / Phi Silica** | Foundry Local offers Windows CPU/GPU/NPU model variants, subject to device/Windows prerequisites. Phi Silica's platform-card context is about **3.5k tokens** and access is restricted/transitioning; it is unsuitable for whole-hour Ask and would need retrieval even if available. [Foundry Local quickstart](https://learn.microsoft.com/en-us/windows/ai/foundry-local/get-started), [Phi Silica platform card](https://learn.microsoft.com/en-us/windows/ai/cards/phi-silica-platform-card), [Phi Silica API](https://learn.microsoft.com/en-us/windows/ai/apis/phi-silica) |
| **OpenAI or Anthropic API, BYOK** | A user-provided API key can call a long-context cloud model with structured output; this is the most straightforward quality fallback, while transcript excerpts leave the device and token charges vary by model. Store credentials in the Windows credential store; show which evidence is sent. API access and consumer subscriptions are separate products unless an explicitly documented plan-usage flow applies. [OpenAI model pricing](https://platform.openai.com/pricing), [Anthropic pricing](https://platform.claude.com/docs/en/about-claude/pricing), [Windows Credential Manager](https://learn.microsoft.com/en-us/windows/win32/secauthn/credentials-management) |

**Reuse of installed coding CLIs.** `codex exec` and `claude -p` are documented non-interactive interfaces, so a desktop process could technically invoke them. They are coding-agent CLIs with account, workspace, permission, output and version behavior that a consumer meeting app should not silently inherit. Do not make them the shipping Ask backend or read their credential files. [OpenAI on `codex exec`](https://developers.openai.com/blog/codex-as-a-platform), [Claude Code headless docs](https://code.claude.com/docs/en/headless)

For OpenAI, a **different, documented route** now exists: Sign in with ChatGPT can authorize eligible Responses API calls against a user's ChatGPT plan for **open-source, locally hosted apps** through OAuth. The docs say paid or remotely hosted apps should use an interest form. The preview requires `store:false`, `stream:true`, full request context and other restrictions; **audio input and the transcription API are excluded**, so this route could cover text Ask but not Transcribe. It also documents a Codex app-server integration, but the app should use the direct documented OAuth/Responses flow if it qualifies rather than commandeering an existing `codex exec` login. This is a promising **optional** Ask route only after checking the app's distribution, licensing and current eligibility; it is not a general subscription-to-API entitlement. [Plan-usage overview](https://developers.openai.com/siwc/token-sharing-open-source), [quickstart](https://developers.openai.com/siwc/quickstart), [preview limits](https://developers.openai.com/siwc/token-sharing-open-source/preview-limitations), [Codex app-server](https://developers.openai.com/siwc/token-sharing-open-source/codex-app-server)

For Anthropic, `claude -p` exists and Anthropic documents some Claude-plan usage for the Agent SDK/CLI, but its login policy directs builders of third-party products to API keys and warns against routing third-party app traffic through subscription limits. Treat CLI-subscription use in a distributed Meeting Minutes app as a **terms and product risk**; choose Anthropic API BYOK unless Anthropic explicitly approves the integration. This is a reading of current official guidance, not legal advice. [Claude Code headless](https://code.claude.com/docs/en/headless), [plan-use help](https://support.claude.com/en/articles/15036540-use-the-claude-agent-sdk-with-your-claude-plan), [Claude login policy](https://support.claude.com/en/articles/13189465-log-in-to-your-claude-account)

## 5. Segment and citation contract

Implement one provider-neutral transcript format. Example (illustrative):

```json
{"meeting_id":"m42","revision":1,"segments":[{"id":"s000184","start_ms":723410,"end_ms":728960,"text":"...","speaker":"remote_audio"}]}
```

1. **After explicit Transcribe**, normalize provider output to ordered, nonempty ranges (`0 <= start_ms < end_ms <= duration_ms`), preserve source text, and assign IDs in the app/database. Save source model, language, track, job/chunk offsets and transcript revision. Do not use a model timestamp or a provider's mutable segment index as the durable citation key. On re-transcription, create a new revision and do not silently redirect old citations. This is a proposed invariant informed by timestamped ASR formats. [OpenAI transcription formats](https://developers.openai.com/api/docs/guides/speech-to-text), [Deepgram diarization response](https://developers.deepgram.com/docs/diarization)
2. For Ask, pass only permitted segments as records such as `[s000184] text`; ask for `{answer, evidence:[{segment_id}], insufficient_evidence}`. Require an explicit insufficient-evidence state and an empty evidence list when the answer is unsupported. Use the provider's strict JSON-schema mode where available; schema enforcement guarantees shape, **not** that the claim is true. [OpenAI structured outputs](https://developers.openai.com/api/docs/guides/structured-outputs), [Anthropic structured outputs](https://platform.claude.com/docs/en/build-with-claude/structured-outputs), [Ollama structured outputs](https://docs.ollama.com/capabilities/structured-outputs)
3. Validate the parsed result in app code: each ID must exist in the current meeting/revision and preferably in the evidence set supplied for that question; reject nonexistent/cross-meeting IDs, empty support for substantive claims, or answer text containing model-written timestamps as references. Render citations as `meeting_id + segment_id` links and derive visible `mm:ss`/audio seek positions **only from stored `start_ms`/`end_ms`**. Check source text against each claim, and abstain or retry when support is weak. Strict output alone cannot verify semantic support. [OpenAI structured-output limitations](https://developers.openai.com/api/docs/guides/structured-outputs)
4. Anthropic's native citations can return pointers to supplied custom-content blocks; supplying one transcript segment per block is another viable path. Its native citations and strict JSON output format cannot currently be used together, so select one route and still validate meeting scope. [Anthropic citations](https://platform.claude.com/docs/en/build-with-claude/citations)

## Ranked risks and decision gates

1. **Transcript truth and bilingual quality.** Hallucinated words or weak Vietnamese/code-switch recognition contaminate every later answer. Gate: labeled English/Vietnamese meeting set, WER/CER, overlap/noise cases, and correction workflow. [Whisper model card](https://github.com/openai/whisper/blob/main/model-card.md)
2. **Citation truth.** A valid segment ID can support the wrong claim. Gate: claim-to-evidence review set, cross-meeting rejection, insufficient-evidence cases, and source-derived seek times; keep schema and semantic checks separate. [OpenAI structured-output limitations](https://developers.openai.com/api/docs/guides/structured-outputs)
3. **Windows hardware variance.** Desktop benchmark and H100/A100 model-card figures are not laptop SLAs; NPU availability differs by device and API. Gate: 60-minute benchmarks on CPU-only, integrated-GPU, NVIDIA and Copilot+ machines, including packaging and thermals. [faster-whisper benchmark](https://github.com/SYSTRAN/faster-whisper), [Windows ML providers](https://learn.microsoft.com/en-us/windows/ai/new-windows-ml/supported-execution-providers), [Parakeet card](https://huggingface.co/nvidia/parakeet-tdt-0.6b-v3)
4. **Speaker errors and capture bleed.** Two tracks distinguish local mic from rendered audio, not individual remote people; overlapping/cross-talk makes attribution uncertain. Gate: synchronized-track and echo/overlap tests; keep speaker unknown when uncertain. [WASAPI loopback](https://learn.microsoft.com/en-us/windows/win32/coreaudio/loopback-recording), [pyannote](https://github.com/pyannote/pyannote-audio)
5. **Cloud limits, privacy, cost and plan eligibility.** An hour can exceed OpenAI's file cap; pricing and OAuth preview terms change; cloud Ask sends transcript evidence. Gate: chunk/offset tests, per-provider cost confirmation, explicit user choice, and qualification for any plan-usage program. [OpenAI file guide](https://developers.openai.com/api/docs/guides/speech-to-text), [OpenAI plan-usage overview](https://developers.openai.com/siwc/token-sharing-open-source)

**Decision:** ship the same local segment store and citation validator for every route. Offer (A) local `whisper.cpp` + local retrieved Ask as the privacy-first baseline, (B) managed cloud STT/Ask only if the product commits to operating that service, or (C) BYOK cloud STT/Ask for users who want speed/quality without a managed AI subscription. A locally hosted open-source release may later add the documented OpenAI plan-usage OAuth route for Ask, contingent on eligibility; avoid CLI subscription tunneling as a product dependency. [whisper.cpp](https://github.com/ggml-org/whisper.cpp), [OpenAI plan-usage overview](https://developers.openai.com/siwc/token-sharing-open-source), [Anthropic login policy](https://support.claude.com/en/articles/13189465-log-in-to-your-claude-account)
